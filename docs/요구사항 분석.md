# 요구사항 분석

## 1. 잔액 충전 / 조회

### 기능적 요구사항

1. 사용자는 잔액을 충전한다.
2. 사용자는 본인의 현재 잔액을 조회한다.
3. 포인트는 누적 방식으로 증가한다.
4. 충전 금액은 0보다 커야한다.
5. 충전은 최대 한도를 넘게 충전 할 수 없다.
6. 잔액 충전 성공 후 포인트 이력 테이블에 저장 되어야한다.

### 비기능적 요구사항

1. 잔액 충전에 대한 중복 요청시 정합성을 보장한다.
2. 충전과 사용이 동시에 일어나도 일관성을 유지한다.
   
---

## 2. 상품 조회

### 기능적 요구사항

1. 상품 ID를 기준으로 상품 정보를 조회한다.
2. 상품이 존재하지 않을 경우, 에러 메시지를 반환해야한다.

---

## 3. 상품 주문

### 기능적 요구사항

1. 사용자는 상품ID와 수량을 포함한 구매 요청을 보낸다.
2. 요청 받은 상품의 재고를 확인해야 한다.
3. 재고가 부족할 경우, 주문은 취소되고 에러 메시지를 반환해야한다.
4. 재고가 충분할 경우, 주문 정보를 저장한다.
5. 사용자 포인트를 조회후 상품 금액을 차감한다.
6. 사용자의 포인트를 차감 후, 상품 재고를 차감한다.
7. 모든 주문이 완료되면 주문 완료 응답을 반환한다.

### 비기능적 요구사항
1. 주문, 포인트 차감, 재고 차감은 하나의 트랜잭션에서 처리가 되어야한다.
2. 재고 감소의 동시성 제어 필요


---

## 4. 선착순 쿠폰

### 기능적 요구사항

1. 사용자는 지정된 쿠폰ID로 발급을 요청한다.
2. 해당 쿠폰ID가 유효한지 확인한다.
3. 쿠폰이 존재하지 않는다면, 에러 메시지를 반환한다.
4. 쿠폰이 존재하면, 잔여 수량을 조회한다.
5. 잔여 수량이 있다면 쿠폰을 발급한다.


### 비기능적 요구사항

1. 다수의 요청이 동시에 들어와도 중복 발급 없이 잔여 수량만큼 정확하게 차감해야한다.


---

## 5. 상위 상품 조회

### 기능적 요구사항

1. 최근의 기준을 정한 후, 그 기준으로 상위 상품을 조회한다.
2. 상위의 기준을 정한 후, 그 기준으로 상품의 개수를 반환한다.
